# 7주차 핵심 키워드

## 인증과 인가

- **인증(Authentication)**: 요청한 사람이 누구인지 확인하는 과정이다. 예를 들어 로그인할 때 이메일과 비밀번호를 확인하고 사용자 신원을 식별한다.
- **인가(Authorization)**: 확인한 사용자가 특정 데이터나 기능을 이용해도 되는지 판단하는 과정이다. 로그인했어도 다른 사람의 프로필을 수정하거나 관리자 메뉴를 사용할 수는 없다.
- 화면에서 버튼을 숨겨도 요청을 직접 보낼 수 있으므로, 실제 권한 검사는 서버가 매 요청마다 수행해야 한다. 이번 주 `/my` 화면은 퍼블리싱용으로 누구나 접근할 수 있으며 인증·인가 구현을 의미하지 않는다.

## JWT

로그인 이후 사용자에 관한 정보를 전달할 때 사용하는 토큰 형식이다. 워크북에서 다루는 일반적인 서명된 JWT(JWS)는 `header.payload.signature`로 구성된다. JWT에는 암호화된 JWE 형식도 있지만, 서명된 JWT 자체는 내용을 숨기지 않는다.

| 구성 | 역할 | 예시 |
| --- | --- | --- |
| Header | 토큰 유형과 서명 알고리즘 정보 | `typ`, `alg` |
| Payload | 사용자 ID, 만료 시각 등 클레임 | `sub`, `exp` |
| Signature | 서명 대상의 변조 여부와 발급 주체 확인에 사용 | 서버가 신뢰하는 키로 검증 |

- **디코딩과 검증**: 디코딩은 Base64url로 표현된 내용을 읽는 과정으로, 누구나 할 수 있다. 내용을 읽었다고 신뢰할 수 있는 것은 아니다. 검증은 허용한 알고리즘과 신뢰하는 키로 서명을 검사하고 만료 시각, 발급자, 수신자 등 필요한 조건도 확인하는 과정이다.
- **비밀번호를 담으면 안 되는 이유**: 서명은 암호화가 아니므로, 토큰을 얻은 사람이 payload를 읽을 수 있다. 비밀번호나 비밀 키를 넣지 않고 필요한 정보만 최소한으로 담는다.
- **프로젝트 연결**: 이번 주에는 회원가입만 API와 연결한다. 로그인 토큰 발급·보관·요청 헤더 연결과 보호된 페이지 접근 제어는 다음 주에 다룬다. 회원 API 클라이언트에 영화 API용 TMDB 토큰을 공유하지 않는다.

참고: [JWT 표준 RFC 7519](https://datatracker.ietf.org/doc/html/rfc7519), [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html).
